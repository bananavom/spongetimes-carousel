# Google Sheets 세팅과 읽기/쓰기 규칙

시트는 **팀원(비개발자 12명 포함)의 입력·열람 창구**다. 레포 CSV는 분석·버전 관리용 정본 스냅샷이다.
두 곳의 컬럼은 `schema.md`와 1:1로 동일하다.

## 시트 구조

시트 이름: `스폰지타임즈 3기 가설검증 로그` (config.json의 `sheet.name`)

| 탭 | 내용 |
|---|---|
| `README` | 한국어 사용법, 컬럼 한국어 라벨 대응표, **현재 베이스라인 요약 블록** |
| `hypotheses` | 가설 로그 — 1행 = schema.md의 CSV 헤더 그대로 |
| `posts_metrics` | 발행+지표 로그 — 동일 |
| `verdicts` | 판정 로그 — 동일 |

### 시트 처음 만들기

1. 사용자가 Google Sheets에서 새 시트를 만들고 탭 4개를 위 이름으로 생성한다.
2. 각 로그 탭의 1행에 아래 헤더를 붙여넣는다 (schema.md의 CSV 헤더와 동일 — 탭으로 구분된 버전을
   스킬이 출력해 주면 그대로 붙여넣으면 된다).
3. README 탭에 스킬이 출력해 주는 사용법·라벨표·베이스라인 요약 블록을 붙여넣는다.
4. 시트 URL을 `config.json`의 `sheet.sheet_url`/`sheet_id`에 기입한다
   (URL의 `/d/`와 `/edit` 사이 문자열이 ID다).
5. 유닛 멤버 전원에게 편집 권한을 공유한다.

## 읽기 폴백 사다리

1. `config.json`의 `sheet_id`로 Google Drive MCP `read_file_content` — 시트가 마크다운 표로 온다.
2. 실패 시 MCP `search_files`로 `sheet.name` 검색 → 찾으면 ID를 config에 기입하도록 안내.
3. MCP가 없거나 실패하면 `data/*.csv` (Claude Code).
4. 그것도 없으면 사용자에게 해당 탭을 복사·붙여넣기 해 달라고 요청한다.

어떤 경로로 읽었는지 한 줄로 알리고 진행하라.

## 쓰기 규칙 (중요)

Drive MCP로 시트 셀을 편집하는 것은 신뢰할 수 없다. 시도해도 되지만 **성공을 가정하지 마라.**
확실한 쓰기 경로는 두 가지이고, 항상 둘 다 제공한다:

1. **Claude Code 환경**: `data/*.csv`에 행을 append (파일이 정본 스냅샷이 된다).
2. **항상**: 시트에 그대로 붙여넣을 수 있는 **탭 구분(TSV) 행 블록**을 코드블록으로 출력한다.
   사용자는 블록을 복사 → 시트 해당 탭의 다음 빈 행 A열 선택 → 붙여넣기 하면 끝이다.

TSV 블록 출력 예시:

```
P-S3W1-01	H-S3W1-01	2026-09-05 12:00	W1	carousel	봄	실사 스크린샷	클로드 실패 화면 모음	https://instagram.com/p/...	24h	2026-09-06 13:00	screenshot	3200	2100	62	38	3400	180	12	45	9	85	6	512	0.0214	0.0043	0.0029	
```

- 컬럼 순서는 schema.md 헤더 순서와 정확히 일치해야 한다. 공란 컬럼도 탭은 유지한다.
- 여러 행이면 줄바꿈으로 잇는다.

## 동기화에 대한 태도

시트와 CSV가 어긋날 수 있다. 어긋남을 발견하면 **행이 더 많은 쪽이 진실**일 가능성이 높다
(둘 다 append-only이므로). 검증(모드 ⑤) 전에 두 소스의 행 수가 다르면 사용자에게 알리고
어느 쪽을 기준으로 할지 확인한 뒤, 부족한 쪽에 채워 넣을 TSV/CSV 블록을 출력해 맞춘다.
