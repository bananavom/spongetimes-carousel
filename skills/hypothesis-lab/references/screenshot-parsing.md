# 인사이트 스크린샷 파싱 가이드 (모드 ④)

인스타그램 인사이트는 API 연동 없이는 자동으로 읽을 수 없다.
그래서 수집 경로는 **사람이 인사이트 화면을 캡처 → 스킬이 숫자를 읽어 표준 스키마로 기록**이다.
콘텐츠당 30초 수준의 수고로 데이터가 쌓인다.

## 수집 요청 시점

- **24시간 후** (일요일 검증 루프의 기본 데이터): 발행 다음 날 캡처
- **7일 후** (확산 꼬리 확인): 일주일 뒤 한 번 더

같은 포스트라도 24h와 7d는 **별도 행**이다. 다른 스냅샷끼리 비교하지 않는다.

## 인사이트 화면 → 스키마 매핑

인스타그램 UI 용어는 한/영, 버전에 따라 다르다. 아래 대응표로 매핑하라.

| 화면 표기 (한국어) | 화면 표기 (영어) | 스키마 컬럼 |
|---|---|---|
| 조회 / 조회수 | Views | `views` |
| 도달한 계정 | Accounts reached | `reach` |
| 노출 | Impressions | `impressions` |
| 팔로워 / 팔로워가 아닌 사람 (%) | Followers / Non-followers | `reach_follower_pct` / `reach_nonfollower_pct` |
| 좋아요 | Likes | `likes` |
| 댓글 | Comments | `comments` |
| 공유 | Shares / Sends | `shares` |
| 저장 | Saves | `saves` |
| 프로필 방문 | Profile visits | `profile_visits` |
| 팔로우 | Follows | `follows` |
| 상호작용 / 참여한 계정 | Interactions / Accounts engaged | (참고용 — 개별 지표가 있으면 그쪽 우선) |
| 재생 시간 / 평균 시청 시간 | Watch time / Avg watch time | `notes`에 기록 (릴스) |

주의:
- 최신 UI는 `노출(impressions)` 대신 `조회(views)`를 상단에 보여준다. 화면에 있는 것만 기록하라.
- 릴스의 "조회수"와 캐러셀의 "조회수"는 집계 방식이 다르지만, 포맷 공통 지표로서 그대로 `views`에 넣는다
  (비교는 항상 같은 포맷끼리 하므로 문제되지 않는다).
- `1.2만` `12.5K` 같은 축약 표기는 정수로 환산한다 (12,000 / 12,500).

## 파싱 세션 절차

1. **포스트 매칭**: 스크린샷이 어느 포스트의 것인지 확인한다.
   화면의 썸네일·캡션·게시일로 추정하고, 확신이 없으면 반드시 물어본다.
   posts_metrics에 메타 행(모드 ③)이 이미 있으면 그 `post_id`를 쓴다. 없으면 메타부터 채운다.
2. **스냅샷 판별**: 발행일과 캡처 시점의 간격으로 `24h`/`7d`를 정한다. 애매하면(예: 3일 뒤 캡처)
   실제 경과를 `notes`에 쓰고 가까운 쪽으로 분류하되 사용자에게 알린다.
3. **숫자 추출**: 대응표로 각 지표를 읽는다. 흐릿하거나 잘린 숫자는 추측하지 말고 물어본다.
4. **결측 처리**: 화면에 없는 지표는 **공란**으로 둔다 (0 아님).
   핵심 지표(`reach`, `saves`, `shares`, 팔로워/비팔로워 %)가 없으면 해당 화면
   (인사이트 상세의 아래쪽 스크롤, "도달한 계정" 화면)을 추가로 요청하라 —
   이 지표들이 없으면 검증(모드 ⑤)이 돌아가지 않는다.
5. **파생지표 계산**: `save_rate = saves/reach`, `share_rate = shares/reach`,
   `follow_conv_rate = follows/reach` (소수 4자리). reach가 공란이면 파생도 공란.
6. **팔로워 수**: 가능하면 현재 팔로워 수를 물어 `follower_count_at_snapshot`에 기록한다.
7. **행 출력**: 완성된 행을 표로 보여 확인받고, 시트 붙여넣기용 TSV 블록을 출력한다.
   Claude Code 환경이면 `data/posts_metrics.csv`에도 append한다.

## 여러 장 일괄 처리 (시딩 포함)

여러 포스트의 스크린샷을 한 번에 받으면 포스트별로 위 절차를 반복하고,
마지막에 전체 행을 하나의 TSV 블록으로 묶어 출력한다.
시즌2 시딩(모드 ⑥)도 같은 절차다 — `week`는 `S2W1` 식으로, `source`는 `screenshot`으로 기록한다.
