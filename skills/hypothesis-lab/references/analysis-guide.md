# 검증·분석 가이드 (모드 ⑤)

## 파생지표 공식

율(rate) 지표를 쓰는 이유: 팔로워가 늘면 절대값(저장 수, 도달 수)은 저절로 커진다.
율은 콘텐츠 자체의 힘을 팔로워 규모에서 분리해 준다.

| 지표 | 공식 | 의미 |
|---|---|---|
| 저장률 `save_rate` | `saves / reach` | 다시 볼 가치 — 캐러셀의 핵심 지표 (저장이 배포를 결정한다) |
| 공유율 `share_rate` | `shares / reach` | 퍼뜨릴 가치 |
| 팔로우 전환율 `follow_conv_rate` | `follows / reach` | 유입 → 팔로워 전환 |
| 비팔로워 도달 비율 | `reach_nonfollower_pct` | 계정 밖으로 나갔는가 — 릴스의 핵심 지표 |
| 조회/도달 배율 | `views / reach` | 한 명이 몇 번 봤는가 (재소비 신호) |
| 프로필 방문율 | `profile_visits / reach` | 계정 궁금증 유발 |

포맷별 우선 지표 (콘텐츠 역할 정의에 따름):
- **릴스** = 도달 담당 → `reach_nonfollower_pct`, `views`, `reach`
- **캐러셀** = 전환 담당 → `save_rate`, `share_rate`, `follow_conv_rate`
- **스토리** = 팔로워 접점 → `views`, 반응(답장·공유)

## 비교 절차

1. 가설의 `target_metric`, `success_threshold`, `comparison_design`을 로드한다.
2. 실험군 값을 구한다 (포스트 여러 개면 평균).
3. 대조값을 구한다:
   - `baseline` → `baseline.json`의 같은 포맷 해당 지표
   - `paired` → 짝 포스트의 같은 스냅샷 행
   - `prepost` → 전 기간 posts_metrics 평균
4. `delta_pct = (실험값 - 대조값) / 대조값 × 100`
5. **같은 스냅샷끼리만** 비교했는지 확인한다 (24h vs 24h).

## 퍼널 진단

수치 하나로 판정하고 끝내지 말고, 퍼널 어디서 이탈했는지 읽어라. 다음 가설이 여기서 나온다.

```
노출/조회 (views, impressions)
   │  ← 조회 자체가 적다 = 알고리즘이 밀지 않았다 (초기 반응 부족 or 포맷 문제)
   ▼
도달 (reach) · 비팔로워 비율
   │  ← 도달 중 팔로워 비율이 높다 = 계정 안에서만 소비됐다 (2기의 88.2% 문제)
   ▼
반응 (saves, shares, comments)
   │  ← 도달은 됐는데 저장·공유가 없다 = 다시 볼 이유·퍼뜨릴 이유를 못 만들었다
   │     (첫 장은 통했지만 본문이 약했을 가능성 → 캐러셀이면 장별 이탈 의심)
   ▼
프로필 방문 (profile_visits)
   │  ← 반응은 있는데 방문이 없다 = 콘텐츠는 소비됐지만 계정 궁금증까지는 못 갔다
   ▼
팔로우 (follows)
      ← 방문은 있는데 팔로우가 없다 = 그리드/프로필이 전환 실패 (콘텐츠 문제 아님)
```

진단 문구는 `funnel_diagnosis` 컬럼에 짧게 기록한다
(예: "표지 후킹 실패", "본문 이탈", "비팔로워 도달 부족", "그리드 전환 실패").

## 판정 기준

| 판정 | 조건 |
|---|---|
| **지지** | 임계값 충족 + 교란변수로 결과가 설명되지 않음. 1회차면 "지지(1회)"로 쓰고 같은 변수 반복을 제안 |
| **기각** | 임계값 미달이 뚜렷 (대조 대비 -20% 이하이거나 임계값의 절반 이하) + 교란 없음 |
| **판단불가** | 핵심 지표 결측 / 교란변수가 결과를 설명할 수 있음 / 차이가 ±20% 이내로 운과 구분 불가 |

원칙:
- 교란이 의심되면 지지 쪽으로 무리하지 마라. 오염된 "지지"가 쌓이면 베이스라인과 다음 가설이 전부 오염된다.
- **기각도 성과다.** `learning`에는 "무엇이 아니라는 걸 알았는가"와 다음 가설 제안을 반드시 채운다.
- 판정 후 처리: 가설 행 `status` → `검증완료`, `verdict_id` 기입 → 모드 ⑥ 베이스라인 갱신 제안.
