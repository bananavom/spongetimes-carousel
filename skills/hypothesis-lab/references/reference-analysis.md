# 레퍼런스 수집·해부 (모드 ⓪)

레퍼런스는 가설의 원료다. 이 모드의 목표는 두 가지:
(1) 발견 즉시 쌓아둬서 월요일 가설 수립 때 재료가 준비돼 있게 하고,
(2) "좋았어요"가 아니라 **스폰지타임즈에 적용 가능한 포인트**까지 뽑아내는 것.

## 콘텐츠 받는 법

| 전달 형태 | 처리 |
|---|---|
| 이미지 (캐러셀 장 캡처, 표지 등) | 직접 분석. 여러 장이면 장 순서를 물어 확인 |
| 영상 (릴스 파일/화면녹화) | 직접 분석. 첫 3초 훅을 특히 뜯는다 |
| 링크 (instagram.com/...) | 인스타그램 로그인월 때문에 열리지 않는 경우가 많다. 열어보되, 실패하면 링크·계정·포맷 등 메타만 기록하고 **화면 캡처를 요청**하라. 링크만으로 내용을 추측해서 해부하지 말 것 |

여러 콘텐츠를 한 번에 받으면 콘텐츠마다 아래 해부를 반복하고,
마지막에 **공통 패턴 요약**(반복 등장하는 훅 구조·형식)을 덧붙인다. 공통 패턴이야말로
한 편의 우연이 아니라 계정의 전략이므로 가설 후보 가치가 높다.

## 3칸 해부 (콘텐츠마다)

발표 자료의 해부 프레임 그대로:

| 칸 | 질문 | 예시 |
|---|---|---|
| **고정 요소** | 매 편 똑같은 것은? | 질문 세트, 자막 스타일, 표지 규칙, 컬러 |
| **변수 요소** | 편마다 바뀌는 것은? | 사람, 소재, 툴, 배경 |
| **후킹 요소** | 손이 멈춘 이유는? | 릴스 = 첫 3초, 캐러셀 = 표지 문구. 숫자/질문/결과 공개 중 무엇인가 |

관찰 가능한 공개 지표(좋아요·댓글 수 등)가 보이면 `visible_metrics`에 기록한다 —
계정 규모 대비로 읽어야 하므로 팔로워 수도 함께 적는 게 좋다.

## 필수 질문: "이걸 스폰지타임즈에 적용한다면?"

이 답이 `apply_point`다. 이게 비어 있으면 해부가 끝난 게 아니다.
좋은 apply_point는 스폰지타임즈의 고정 요소(노랑 악센트, 후크 문장 구조, 캐릭터 스티커)를
지키면서 무엇을 바꿔볼지를 말한다.

이어서 **가설 후보**를 한 문장 형식으로 초안한다 — 측정 지표까지 포함해서:
> "AI에 관심 있는 직장인에게 '실패 화면 공개' 훅으로 스크린샷 캐러셀을 보여주면
> 저장률이 베이스라인의 1.3배 이상일 것이다"

지금 주차의 변수와 맞지 않아도 괜찮다. `status=보관`으로 쌓아두면
모드 ①이 매주 이 로그를 읽고 재료로 제안한다.

## references 로그 기록

스키마는 `schema.md`의 references 절 참고. 핵심 규칙:
- ID는 `R-YYYYMMDD-일련2자리` (예: `R-20260826-01`) — 주차와 무관하게 상시 쌓이므로 날짜 기반.
- 한 계정에서 여러 편을 뜯었으면 편마다 1행 (공통 패턴은 각 행의 notes 또는 요약 출력으로).
- 가설로 채택되면 `status=가설화됨` + `linked_hypothesis_id` 기입 (모드 ①에서 수행).
- 더 이상 유효하지 않은 레퍼런스는 `status=폐기` (행 삭제는 하지 않는다).
- 항상 시트 붙여넣기용 TSV 블록을 함께 출력한다.

## 해부 카드 출력 형식

```
## 🔍 레퍼런스 해부 — {ref_id}
{계정} · {포맷} · {한 줄 설명} {(공개 지표)}

| 고정 요소 | 변수 요소 | 후킹 요소 |
|---|---|---|
| ... | ... | ... |

**스폰지타임즈에 적용한다면**: {apply_point}
**가설 후보**: {한 문장, 지표 포함} → status: 보관
```
