# 레퍼런스 수집·해부 (모드 ⓪)

레퍼런스는 가설의 원료다. 이 모드의 목표는 두 가지:
(1) 발견 즉시 쌓아둬서 월요일 가설 수립 때 재료가 준비돼 있게 하고,
(2) "좋았어요"가 아니라 **스폰지타임즈에 적용 가능한 포인트**까지 뽑아내는 것.

## 콘텐츠 받는 법

| 전달 형태 | 처리 |
|---|---|
| 이미지 (캐러셀 장 캡처, 표지 등) | 직접 분석. 여러 장이면 장 순서를 물어 확인 |
| 영상 (릴스 파일/화면녹화) | 직접 분석. 첫 3초 훅을 특히 뜯는다 |
| 링크 (instagram.com/...) | 인스타그램 로그인월 때문에 열리지 않는 경우가 많다. 열어보되, 실패하면 링크·계정·포맷 등 메타만 기록하고 **화면 캡처를 요청**하라. 링크만으로 내용을 추측해서 해부하지 말 것 |
| 계정 분석 리포트 PDF | Snipit AI 등 외부 도구의 리포트. 텍스트를 추출해 계정 지표·강점·보완점·상위 게시물을 읽고, **표지 이미지가 임베드돼 있으면 추출해 카피를 판독**하라 (리포트 본문에 없는 가장 값진 정보다). 아래 "리포트가 채워주지 않는 칸" 참고 |

여러 콘텐츠를 한 번에 받으면 콘텐츠마다 아래 해부를 반복하고,
마지막에 **공통 패턴 요약**(반복 등장하는 훅 구조·형식)을 덧붙인다. 공통 패턴이야말로
한 편의 우연이 아니라 계정의 전략이므로 가설 후보 가치가 높다.

## 3칸 해부 (콘텐츠마다)

발표 자료의 해부 프레임 그대로:

| 칸 | 질문 | 예시 |
|---|---|---|
| **고정 요소** | 매 편 똑같은 것은? | 질문 세트, 자막 스타일, 표지 규칙, 컬러 |
| **변수 요소** | 편마다 바뀌는 것은? | 사람, 소재, 툴, 배경 |
| **후킹 요소** | 손이 멈춘 이유는? | 릴스 = 첫 3초, 캐러셀 = 표지 문구. 숫자/질문/결과 공개 중 무엇인가 |

관찰 가능한 공개 지표(좋아요·댓글 수 등)가 보이면 `visible_metrics`에 기록한다 —
계정 규모 대비로 읽어야 하므로 팔로워 수도 함께 적는 게 좋다.

### 후킹 요소는 표지를 문자 그대로 뜯는다

"후킹이 좋았다"로 끝내면 재현할 수 없다. 레퍼런스 계정 15개 표지를 전수 관찰한 결과
(→ `data/references.csv` R-20260826-05) 반복되는 문법이 있었으므로, 아래 축으로 분해하라:

| 축 | 확인할 것 |
|---|---|
| **카피 원문** | 표지 문구를 그대로 옮겨 적는다. 요약 금지 |
| **줄 구조** | 관찰한 15/15가 2줄 — 1행=조건·대상(작게), 2행=약속·결론(크게) |
| **종결 형태** | `~하는 법` `~하는 이유` `~안 하는 것` 같은 **명사형 종결**이 지배적 (저장·검색되는 형태) |
| **프레임 유형** | 금기(`티 안나게 베끼는 법`) · 부정/금지(`절대 안 하는 것`, `틀린 겁니다`) · 진짜(`유행하는 진짜 이유`) · 숫자(`4주 루틴`) · X/O 대조 |
| **정보 노출도** | 표지에서 결론을 아끼는가, 리스트를 통째로 노출하는가 — 후자가 비팔로워 도달 최고 성과였다 |
| **첫 3초 (릴스)** | 표지 카피와 **별개**다. 인사(`안녕하세요`)로 시작하는지, 대화 중간 연결어(`그러면 이제`, `여기까지 왔다면`)로 던지는지 |

가장 성과가 좋았던 조합은 **금기 프레임 + 명확한 댓글 CTA**(댓글 8,800)와
**표지에 X/O 리스트 통째 노출**(조회 = 팔로워의 2.8배)이었다. 도달용과 반응용은
포맷이 다르다는 뜻이므로, 적용 포인트를 쓸 때 어느 쪽을 노리는지 명시하라.

### 노리는 행동이 콘텐츠 주제와 일치하는가

같은 계정의 세 콘텐츠가 서로 다른 지표로 터졌다: 댓글 7.2배 / 공유 3.6배 / 조회 2.8배.
우연이 아니라 **콘텐츠마다 노리는 행동을 먼저 정하고, 그 행동이 자연스러운 구조를 만든** 결과다.

가장 선명한 예가 공유형이다 (`R-20260826-10`). 주제가 "친구 영상을 제대로 도와주는 법 =
끝까지 보기·댓글·공유"인데, 그런 내용을 담은 영상을 친구에게 공유하는 것은 **주제의 귀결**이
된다. 캡션 끝의 "인스타 하는 친구가 있다면 꼭 이 영상도 공유해주세요"는 요청이 아니라
확인 사살에 가깝다. 실제로 이 레퍼런스를 우리가 본 경로도 제3자의 스토리 공유 화면이었다.

그래서 해부할 때 이 질문을 하라: **"이 콘텐츠는 어떤 행동을 노리는가, 그리고 그 행동이
콘텐츠 주제에서 자연스럽게 나오는가?"** CTA를 뒤에 붙이는 것과 주제가 행동을 낳는 것은 다르다.

### 규모가 다른 계정과 비교할 때

좋아요율은 계정 규모에 따라 기준선이 달라 절대 비교가 무의미하다
(스폰지클럽 500명 2.77% vs 레퍼런스 85K 0.76% — 둘 다 정상 범위).
규모 중립적으로 읽히는 지표는 이 셋이다:

- **댓글 : 좋아요 비율** — 보통 1:5~1:20인데, 1:1에 가까우면 댓글 CTA를 상시 운용하는 계정이다
  (스폰지클럽 0.21 vs 레퍼런스 0.98). 계정의 "정체"가 이 한 지표에서 드러난다.
- **조회수 ÷ 팔로워 배수** — 1을 크게 넘으면 비팔로워로 퍼진 콘텐츠다.
- **TOP3 ÷ 평균 배수** — 편차가 크면 우연 의존, 작으면 재현 가능한 공식을 가진 계정.

## 필수 질문: "이걸 스폰지타임즈에 적용한다면?"

이 답이 `apply_point`다. 이게 비어 있으면 해부가 끝난 게 아니다.
좋은 apply_point는 스폰지타임즈의 고정 요소(노랑 악센트, 후크 문장 구조, 캐릭터 스티커)를
지키면서 무엇을 바꿔볼지를 말한다.

이어서 **가설 후보**를 한 문장 형식으로 초안한다 — 측정 지표까지 포함해서:
> "AI에 관심 있는 직장인에게 '실패 화면 공개' 훅으로 스크린샷 캐러셀을 보여주면
> 저장률이 베이스라인의 1.3배 이상일 것이다"

지금 주차의 변수와 맞지 않아도 괜찮다. `status=보관`으로 쌓아두면
모드 ①이 매주 이 로그를 읽고 재료로 제안한다.

## references 로그 기록

스키마는 `schema.md`의 references 절 참고. 핵심 규칙:
- ID는 `R-YYYYMMDD-일련2자리` (예: `R-20260826-01`) — 주차와 무관하게 상시 쌓이므로 날짜 기반.
- 한 계정에서 여러 편을 뜯었으면 편마다 1행 (공통 패턴은 각 행의 notes 또는 요약 출력으로).
- 가설로 채택되면 `status=가설화됨` + `linked_hypothesis_id` 기입 (모드 ①에서 수행).
- 더 이상 유효하지 않은 레퍼런스는 `status=폐기` (행 삭제는 하지 않는다).
- 항상 시트 붙여넣기용 TSV 블록을 함께 출력한다.

## 리포트가 채워주지 않는 칸 (외부 분석 도구를 쓸 때)

Snipit 같은 자동 분석 리포트는 계정 지표·총평·상위 게시물·강점/보완점까지는 주지만,
**우리가 가설을 세우는 데 필요한 것들은 빠져 있다.** 리포트를 받았다면 아래가 비어 있음을
전제하고, 필요한 것은 스크린샷·캡처로 따로 요청하라:

- 포맷 믹스와 포맷별 성과 (릴스 vs 캐러셀 비율·차이)
- 게시 빈도·요일·시간대
- **저장·공유·도달·프로필 방문** — 좋아요/댓글만 나온다
- 해시태그 실사용 분석 (컨셉 요약 태그와 혼동 금지)
- 캡션 원문, 표지 카피 (이미지 추출로만 얻을 수 있다)

또한 리포트의 서술을 사실로 받아들이기 전에 근거가 있는지 보라. 예를 들어 스폰지클럽
리포트는 "릴스 인게이지먼트가 높다"고 제언하지만 포맷별 데이터를 전혀 제시하지 않는다 —
이런 건 **베이스라인에 넣지 말고 미검증 가설로 분류**한다.

## 해부 카드 출력 형식

```
## 🔍 레퍼런스 해부 — {ref_id}
{계정} · {포맷} · {한 줄 설명} {(공개 지표)}

| 고정 요소 | 변수 요소 | 후킹 요소 |
|---|---|---|
| ... | ... | ... |

**스폰지타임즈에 적용한다면**: {apply_point}
**가설 후보**: {한 문장, 지표 포함} → status: 보관
```
